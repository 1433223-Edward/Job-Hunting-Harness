# Job Hunting Agent：BOSS JD 最小提取原型

本次是根据当前代码职责进行简化，不是对 17:24 前历史版本的精确回滚：工作区没有 Git 历史。未重置仓库或改动无关文件。

## 当前执行链路

点击扩展图标 → 点击“读取当前页面” → `chrome.tabs.query` 查询活动标签页 → `chrome.scripting.executeScript` 按需读取 → 唯一文本规则清洗 → 主文本框展示 → 复制按钮复制该文本框内容。

- JD 定位保留已有的可见“职位描述”标题与父级查找，选中包含实际内容的最小候选祖先。不再向更大的容器扩展，也不推断招聘者边界。
- 无法确认唯一候选时回退 `document.body.innerText` 并提示。普通网页的全文读取保留。
- 对选中来源直接读取 `innerText`，不做逐子区域渲染、章节拆分或关键词删除。MySQL/Python、编号、所有 JD 子章节都随正文保留。
- 与结束边界无关的既有职位摘要读取保留；不能可靠识别的摘要字段显示未知。
- 正文最多返回 30000 个 JavaScript UTF-16 代码单元，并显示长度和截断状态。关闭弹窗后结果丢失。

## 固定文本清洗规则

所有规则集中在 `cleanBossJD(rawText)` 中，返回 `{ text, boundary }`：

1. 仅清理最开头的“微信扫码分享”和“举报”操作区域，支持操作词之间的空格、换行及“举\n报”。若前面有“职位描述”标题则保留标题。遇到技能标签、正文或其他文字即停止，不全局替换相同词语。
2. 查找“竞争力分析”和“认证资质”，以首次出现的标记作为结束位置，删除该标记及后文。两个标记都没有时不截断正文，弹窗提示未命中（仍会清理明确的开头操作区域）。
3. 不 trim 或改写正文，不识别招聘者；技能、编号、职责、要求与加分项原文和顺序保留。

规则在提取结果生成后、主文本显示前执行。复制功能读取同一主文本框。清洗前原始提取结果单独保留供对照（最多 30000 个代码单元），不写日志、不自动持久化。

## 本轮删除的复杂逻辑

- 招聘者姓名、活跃状态、公司、身份组合识别，以及 DOM/多行文本两套招聘者边界规则。
- 为寻找结束边界增加的兄弟节点扫描、祖先容器扩展、Range 截断和特殊模块判断。
- DOM 子区域分类、跳过节点集合、递归重建正文、单独技能标签猜测。
- 复杂章节切分、章节编号/偏移元数据和依赖章节的冲突分析；相应的章节/冲突界面一并移除。
- 旧版招聘者专用前后缀清洗；目前仅保留上述统一函数内的两项固定文本规则。

保留活动页读取、按需注入、可见性检查、简单 JD 定位、全文回退、职位摘要、原文查看、加载状态、字符上限、复制和错误恢复。权限仍只有 `activeTab` 与 `scripting`。

## 文件作用

- `manifest.json`：Manifest V3 配置和最小权限；`activeTab` 提供用户触发后的临时访问，`scripting` 允许按需执行读取函数。
- `popup.html`、`popup.css`：弹窗界面与样式。
- `popup.js`：读取、简单定位、固定边界清洗、显示与复制。
- `tests/clean-boss-jd.test.cjs`：固定边界与用户真实 JD 文本测试，仅使用 Node 内置库。
- `tests/extraction.test.cjs`：使用已有 Playwright 的开发期 DOM/弹窗回归，不增加扩展运行依赖。
- `tests/fixtures/boss-user-raw.txt`：用户此前提供的真实提取文本，保持不变。

## 加载和验证

1. 打开 `chrome://extensions`，开启开发者模式。
2. 点击“加载已解压的扩展程序”，选择直接包含 `manifest.json` 的本目录；已加载则点击该扩展的刷新按钮。
3. 关闭旧弹窗，打开普通网页，重新打开插件测试读取与复制。
4. 打开 BOSS 职位详情页，等待内容加载后读取。
5. 核对职责、要求、加分项及技能均保留；命中时主文本没有最早出现的“竞争力分析”或“认证资质”及其后文；未命中时不截断正文并提示。开头操作词清除，正文中的同词保留。
6. 将复制内容粘贴到本地文本编辑器，与主文本框核对；原始结果区域仍可查看清洗前内容。无需打开 F12。

## 实际执行的检查

- JavaScript 语法、Manifest JSON 和最小权限检查通过。
- 用户真实 JD 仅清理已确认的开头操作区域，正文逐字不变；在真实 JD 后追加明确标记的构造结束标记尾部后，按最早标记移除后文。职责 7 条、要求 8 条、加分项 2 条，以及 MySQL/Python 和最终 LoRA/QLoRA 句子完整保留。
- 单元检查覆盖双标记先后顺序、未命中、空输入、边界在开头、换行保持、开头操作词及“举\n报”、正文同词不误删。
- 21 组无头 Edge 回归通过：简单定向定位、普通页回退、字符上限、既有摘要、主文本与复制一致、原文查看、未命中提示、复制失败和各类读取失败恢复。

在本目录运行：

```powershell
node --check popup.js
node tests/clean-boss-jd.test.cjs
node tests/extraction.test.cjs "<测试环境已有 Playwright 包的绝对路径>"
```

浏览器测试使用构造 DOM 与模拟 Chrome API，未进行真实 Chrome 扩展授权或 BOSS 页面测试。现有 DOM 定位仍需实际页面验收；不会声称能够适配所有 BOSS 布局。

## 范围

仅处理主框架可读取的 DOM 文本，不支持 Chrome 内部页，不读取 iframe、图片文字或未加载内容。不引入 AI、OCR、后端、网络请求或自动投递，不读取 Cookie 或账号凭据。当前规则只处理指定开头操作词和两个固定结束标记，不再推测招聘者边界。
